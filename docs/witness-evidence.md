# Protocol Witness: first hardware evidence

Date: 2026-09-12. Scope: standalone RTL core, not the integrated Tiny Tapeout ASIC.
[Machine-readable snapshot](evidence/witness-core-2026-09-12.json) includes source
hashes and exact test/property names. [ADR 0004](decisions/0004-loadable-witness-core.md)
is the execution contract.

## What can be demonstrated now

1. Load a binary program through the core's synchronous loader. Without changing
   RTL, generate different waveforms and all 256 UART byte values.
2. Sweep request pulse widths 1..8 against a synthetic device that deliberately
   misses pulses shorter than four cycles. Its correct counterpart passes all eight.
3. Capture the smallest failing width within the sweep: one cycle. The terminal
   record reports EXPECT at PC 2, sample cycle 4, expected/masked input 2, observed
   input 0, after three samples. The output enables release on failure.
4. Export its binary words and actual sampled RTL trace to `work/rtl-witness.json`.
   Read the file back, reload the words and compare every replayed cycle and the
   terminal record against the saved result.

This is a toy request/acknowledge device, not an I2C demonstration or a bug found
in existing hardware. The final competition demo should apply the same workflow
to a real protocol implementation and publish the failing case and passing fix.

## Synthesis result and architecture consequence

The current core has **5,151 generic cells**, including **1,528 flip-flops**;
1,280 flip-flops implement the 32 x 40-bit program store. These are generic Boolean
and sequential cells, not CMOS5L standard-cell area or a transistor count.

The first registered-output implementation used two memory read paths and mapped
to 7,101 generic cells. Latching the active instruction reduced the count by 1,950
(27.5%) while preserving registered outputs and no-bubble cycle semantics. Tests
passed before and after the change. This illustrates why we measure early; it
is not a 27.5% silicon-area claim.

The final source hash and cell-type breakdown are in the snapshot. Generated
netlist, synthesis log and local JUnit results live under `work/synthesis/`.

## Reproduce

With the README's Python environment activated:

```sh
make test
make mutations
uv pip install --python .venv/bin/python -r test/synthesis-requirements.txt
make synth-check
make formal
```

The mutation command compiles copies under `work/mutations/`; it never edits the
real RTL. It first requires the unmodified baseline to pass, then requires actual
assertion failures from selected mutants. The formal harness allows arbitrary
control/data inputs after an initial reset; timeout reachability guards against a
wholly inert harness. It is bounded checking, not a complete inductive proof.

## Limits that still matter

The core's loader and witness registers are not wired to physical pins. The current
Tiny Tapeout top still emits the M1 fixed UART. There is no asynchronous input
adapter, host readback transport, RX data queue, SPI/I2C firmware suite or real-device
capture yet. The 32-word capacity needs evaluation against full protocol programs.

No new CMOS5L mapping, place-and-route, static timing, DRC, LVS, Tiny Tapeout precheck
or PDK gate simulation ran for this core. Generic zero-delay netlist simulation
cannot establish the 50 MHz target. The recorded 8x2 layout belongs to the earlier
UART only; the 8x4 tooling/floorplan blocker is unresolved. Timestamp rollover over
a full 2^32-cycle run is not tested. No FPGA or silicon experiment has run.
